# COURTSIDE · 3D Tennis

基于 Three.js 与 cannon-es 的卡通网球游戏。

**在线游玩：https://y523742204.github.io/tennis-game/**

## 运行

需要 Node.js 22 或更新版本，不需要安装 npm 依赖。

```sh
npm start
```

打开 http://127.0.0.1:4173/ 。请通过 HTTP 服务访问，浏览器直接打开 HTML 文件可能拦截 ES Module。

## 操作

- 开始菜单设置每盘 2、4、6 局、对手难度，以及占先制或金球制。
- 指向对方半场选择目标，长按球场展开击球操作。
- 发球：拖动圆盘中心选择平击、上旋、侧旋，支持混合旋转。
- 回球：自己出球后即可长按预选下一拍。向上、左下、右下拖动选择上旋、平击、切削；对手出拍不会重置长按或已锁定的策略。
- 松手锁定力量、球路和目标，到达预判击球点后自动执行；仍按住时按当前选择出手。未操作默认平击。
- 对手打出可追到的网前软球时，自动在落地前截击；下降中的高球处于 2.2～3.5 米高度时可触发高压扣杀。两种动作沿用已选落点与力量，显示各自球种和真实球速；接发球必须等球弹地。
- 长按控件旁的力量条中央金色区域触发 Perfect 暴力击球：球速 +25%，击球体力消耗减少 30%；平击/上旋回球增加下坠旋转。力量条跟随长按位置布局，并避开屏幕边缘。
- 标准满体力平击发球约 180 km/h、底线平击回球约 120 km/h；Perfect 分别约 225 / 150 km/h。每次出拍显示真实初速度，电脑击球也显示。
- 球速会随力量、球路、体力和过网所需弧线变化；低位浅球优先保证过网和落点，因此不保证达到基准速度。显示值是物理模拟中的 km/h，慢动作倍率由 `physics.timeScale` 独立控制。
- 自动接球、击球后回位；跑动与回球消耗体力，一发、二发及擦网重发均不扣发球击球体力，回合中每秒恢复 2 点。
- 每分结束补满至当前上限；本分首次耗尽体力后，下分上限乘以 90%（100→90→81），每局结束恢复至 100。双方独立计算，一发失误和擦网重发不结算体力。
- 体力越低移动越慢；低于 60 点时稳定性逐渐下降，低于 30 点时球速也下降。零体力时球速系数为 70%，落点最大随机偏移 4.2 米（可能出界）。Perfect 仍有加成，但不能免除疲劳影响。
- 平击一发在理想轨迹求解后增加真实出拍角度误差，可能下网或发长；高力量增加误差，Perfect 与侧旋降低误差。此额外惩罚不施加于二发和上旋发球，体力及操作误差仍正常计算。
- `P` 暂停或继续；`Esc` 打开比赛设置；点击球场或空格进入下一分。
- 发球节奏保持原样，回球飞行时间倍率降为 0.52，给预选操作更多时间；真实模拟球速和落点规则不变。
- 本地合成击球、Perfect、弹地、触网、得分音效；首次点击或按键后启用，可在比赛设置关闭。

## 手机与平板

计分板仅显示球员、局数、当前分和发球状态，隐藏单盘比赛中重复的盘数列。

- 支持竖屏、横屏和刘海安全区；球场取景会随屏幕比例重新计算。
- 镜头收近以放大球场与人物；完整比赛区域及底线站位保留在取景中，外围缓冲区实体尺寸不变。
- 触摸对方半场选择目标，保持按住展开圆盘或击球气泡。短距离向上、向左、向右拖动即可选择回球方式。
- 右上角 `⋯` 打开暂停与比赛设置，无需键盘。
- 旋转屏幕或切到后台时会暂停比赛，回到游戏后轻触球场继续。
- 手机端使用较低的渲染分辨率和阴影精度，选球预览按较低频率刷新；球的物理模拟与比赛规则保持一致。

计分包括 15/30/40、占先、金球、局末换发、发球区轮换、双误、擦网重发及抢七。当前为单盘比赛。

## 验证与部署

```sh
npm test
```

主分支更新后，GitHub Actions 运行测试并将 `dist/` 部署到 GitHub Pages。所有网站资源使用相对路径，支持 `/tennis-game/` 项目路径。

## 项目结构

- `dist/`：可直接部署的静态网站。
- `dist/player.js`：卡通球员和关节动画。
- `dist/flight.js`：旋转与空气作用力。
- `dist/tactics.js`：截击、高压、弹跳后击球点与回位。
- `dist/return-strategy.js`：来球预选、锁定及到点执行。
- `dist/viewport.js`：手机取景、安全区、圆盘位置与拖动方向。
- `dist/rules.js`：网球计分与发球顺序。
- `tests/`：物理、策略与规则测试。
- `serve.cjs`：本地静态服务。

第三方依赖固定为 Three.js 0.170.0 与 cannon-es 0.20.0，随网站一同提供，无需 CDN。许可证位于 `dist/vendor/`。

## 调整参数

统一入口为 `dist/config.js`，参数旁有中文说明和单位。修改后重新加载页面；线上需提交部署。

`view.visibleBufferFraction` 控制镜头展示的缓冲区比例（默认 0.45，越小越近）；`physics.serveSideSpin` 控制侧旋幅度（默认 170，为此前两倍）。`tactics.volley* / smash* / airSetupTime` 控制截击和高压的来球高度、速度、网前区域及追球准备时间；`shot.speedKmh.volley / smash` 控制各自基准球速。

| 分组 | 可调整内容 |
| --- | --- |
| `stamina` | 恢复速度、耗尽后的容量保留比例、消耗、低体力惩罚、体力条追赶速度及灰色死区颜色 |
| `movement` | 玩家/三档电脑速度、回位延迟与速度 |
| `shot` / `physics` | 各球路速度、Perfect、力量误差、重力、反弹、摩擦、旋转、空气阻力、模拟步长 |
| `input` / `ai` | 长按、力量循环、Perfect 区域、手势阈值、电脑力量和落点范围 |
| `audio` | 默认音效开关、主音量、各事件音量、击球音色、重复碰撞防抖 |
| `tactics` | 接球高度、站位偏移、候选评分、回位、预测和超时 |
| `animation` / `READY_POSE` / `strokePoses` | 动作时长、击球时机、步频、平滑、拖尾、正反手关节关键姿态 |
| `match` / `court` | 菜单默认值、单打场地与发球区尺寸 |
| `view` / `layout` | 相机、像素倍率、阴影、预览频率、球衣颜色、取景留白及手势布局 |

体力条总刻度固定为 `stamina.full`（默认 100）。可恢复容量为 90 时，补满显示 **90/100**，右侧 10% 为灰色死区；每分结束真实体力补满，但显示值缓慢追赶。调小 `displayRiseRate` 会让恢复动画更慢。

正反手关键帧比例必须满足 `0 < coil < drive < contact < finish < recover < 1`；动作时长、模拟步长和体力总刻度应大于 0。`capRetention` 应在 (0,1]，`minimumMoveMultiplier` 应在 (0,1]。默认菜单局数对应 2/4/6。手势控件设计尺寸与 HTML/CSS/SVG 对齐，修改尺寸时也需要同步布局样式。角色网格拓扑、装饰几何和标准网球计分算法保留在各自实现文件中。

`dist/index.html` 的 import map 为本地模块统一添加缓存版本。部署新代码时应更新其中的版本后缀及入口脚本后缀，避免浏览器混用新旧模块。

球速调参：`shot.serveSpeedKmh` 为发球基准，`shot.speedKmh` 为各球路基准，`shot.perfectSpeed` 为暴力击球倍率，`shot.perfectDipSpin` 为高速回球下坠旋转。`shot.receiverDepth` 控制接发站位，`shot.serveTargetDepth` 控制默认发球深度。`dist/shot.js` 按实际出拍速度求解落点和过网弧线；测速直接使用球的三维速度长度 ×3.6。

节奏调参：`physics.timeScale` 控制发球整段飞行（包含弹地后），`physics.rallyTimeScale` 控制回球。`layout.gesturePowerWidth/Height/Gap` 控制长按位置旁的力量条。声音由 `dist/audio.js` 使用 Web Audio 本地合成，不依赖网络音频资源。

场地采用标准单打 23.77 × 8.23 米、双打 23.77 × 10.97 米尺寸，发球线距网 6.40 米。按 [ITF 国际比赛建议最小缓冲区](https://itf.uberflip.com/i/1255985-facilities-guide/11) 建模：底线后各 6.40 米、双打边线外各 3.66 米，总占地 36.57 × 18.29 米。缓冲区可用于跑动接球，落入缓冲区仍按出界处理。

失误调参：`stamina.stabilityThreshold/maximumScatter/scatterExponent` 控制体力对落点的影响；`shot.flatFirstServeYaw/Pitch` 控制平击一发角度误差；`shot.perfectServeErrorMultiplier` 控制 Perfect 稳定性加成。固定基准力量、默认深区目标、满体力的 512 次种子采样中，平击一发约 60% 进球；这是测试条件下的结果，不是硬编码成功率。
